## 2. 真·公网 IP 判定模块（`/api/pubip`，新页面「真·公网 IP 判定」）

### 你的问题出在哪

原 `detect_public_ip()` 只判两件事：地址是不是公网段、外部回显是否一致。
**它从来没验证过「外网能不能主动连进来」** —— 而这两件事是可以同时成立的：

> 地址是公网段 ✅、回显一致 ✅、但入向被运营商/上级网关封锁 ❌

这正是 `101.70.131.227` 的情况。DDNS 能更新成功、域名也解析得到，别人就是连不上。

### 判定拆成四条独立证据

| 证据 | 说明 | 你的实测结果 |
|------|------|-------------|
| `class` 地址段 | RFC1918 / CGNAT 100.64/10 / 保留段 → 硬否定 | `101.70.131.227` = public ✅ |
| `echo` 多源一致性 | 5 个彼此独立的回显服务交叉验证 | 一致 ✅ |
| `path` 首跳链路 | traceroute 首跳是否私网（多级 NAT 旁证） | `192.168.7.2 → 172.30.144.x` ⚠️ 有私网跳 |
| `inbound` 入向实测 | **唯一能拍板的证据** | 未测试（待你执行） |

### 六级结论

`real` 真公网 · `likely` 疑似公网（未实测）· **`blocked` 有公网地址但入向被拦** ·
`cgnat` 运营商级 NAT · `private` 私有地址 · `unknown` 无法判定（不乱下结论）

你的机器当前判定为 **`likely`** —— 页面会明确告诉你：这一步不能省，去做入向实测。

### 入向实测怎么做的

复现的就是你手动发现问题的那个动作 —— 从另一台外网主机连一次进来：

1. 点「开始入向实测」，页面给出一条可复制的命令，例如 `ping -c 3 101.70.131.227`
2. 在你的 VPS 上执行
3. 本机收到 → 判 `real`；3 分钟没收到 → 判 `blocked`

实现上优先用 `tcpdump` 抓 ICMP echo-request（**零监听端口、零网络改动**），
并排除局域网来源，否则隔壁电脑 ping 一下就会误判成公网可达；
`tcpdump` 不可用时退到一次性 TCP 监听，只用预置高位端口 41000–41005（绝不碰 5900/8443）。

> 真机上 `tcpdump` 未装（是可选依赖），当前走的是 TCP 退路。
> 想用 ICMP 方式的话，在「系统 - 依赖自检」页装 `tcpdump` 即可。

## 3. 依赖自检清单补全（54 → 70 项）

### 根因

你说的「页面提示一键安装，但就绪列表没显示 xfs/f2fs 等名称」，实际有两层：

1. **DEPS 是 54 项平铺列表**，没有分组也没有搜索 —— 70 项里找一个工具只能靠肉眼扫
2. **`e2fsprogs`（mkfs.ext4/ext3）从未登记** —— 而外置存储页的 ext4/ext3 一直在
   提示「请先安装软件包 e2fsprogs」，你在自检页里永远找不到它

### 改动

- DEPS 元组加 `group` 字段（7 → 8），分 11 组：核心 / 系统 / 网络 / 防火墙 /
  外置存储 / 文件共享 / QoS / 打印 / 监控 / 容器 / 桌面
- 补进：`e2fsprogs`、`kmod`、`procps`、`coreutils`、`tar`、`hostname`、`udev`、
  `chronyc`、`snmpd`、`snmp`、`cups`、`cups-client`、`usbutils`、
  `smartmontools`、`lm-sensors`、`dmidecode`
- 前端：**分组过滤 chips + 搜索框**（按名称/命令/包名/说明匹配）+「只看缺失」，
  过滤只在内存里重渲染，不重打接口
- 同步 `make-offline-deps.sh` 与 `deb/control`
  （cups / snmpd / smartmontools 因会拉起常驻服务，只放 Suggests）

## 4. 终端输出延迟与断字优化

| 优化 | 做法 | 效果 |
|------|------|------|
| 长轮询 | 前端发 `wait: 1.2`，服务端无数据时挂起等输出（上限 5s） | 空读挂起 1217ms，有输出 7ms 立刻返回 |
| rAF 批量渲染 | 一帧内多次输出只画一次 DOM | 消除连续同步重排 |
| 宽字符两格 | `wsCharWidth()` + 第二格 `pad` 占位 | 中文/emoji 不再断字 |
| 按码点遍历 | `Array.from` + `WS.carry` 兜底半个代理对 | 不再拆出乱码 |

**命令 → 首字节 6–7 ms**（优化前是数秒级）。

## 顺带修掉的一个部署缺陷（本轮最大的坑）

给终端守护加了长轮询，真机测出来还是 6ms 立刻返回。查下来：

```
install $SRC/backend/drouter-shelld.py $OPT/backend/drouter-shelld.py
...
if ! cmp -s "$SRC/.../drouter-shelld.py" "$OPT/.../drouter-shelld.py"
```

`install` 已经把 SRC 覆盖到 OPT，`cmp` 两边是同一个文件、恒等 ——
**「代码变了就重启」这个分支从来没进过**。进程 16:09 启动，文件 17:40 更新，跑的一直是旧代码。

修法：指纹记在 `/var/lib/drouter/shelld.deployed.sha`（表示**上次真正重启过的版本**），
与本次源码指纹比对；且只有 `systemctl is-active` 真的成功才更新 mark（失败下轮重试）。
新增 `_dev/t-daemon-restart.py`（14 项）守住，已挂进 sync.sh 预检链。

> 这个坑对 helpd 同样成立 —— helpd 目前是每次部署无条件 restart，所以没暴露。
