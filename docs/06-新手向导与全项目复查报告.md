## 一、新手向导（任务 A）

### 位置与形态

**菜单：概览 → 新手向导**（概览组第一位，`needSave: false`）。

选择理由：新手打开 Web 后台的第一眼就该看见它。放进「系统」或「工具」组都要先  
知道去哪找，就失去意义了。`needSave: false` 是因为向导每步自带「保存并生效」  
按钮，页面底部再来一条全局动作条只会让人困惑「我点的保存到底存没存」。

### 四步解决什么

| 步 | 标题       | 解决的原始困惑          | 给的范例                                                      |
| - | -------- | ---------------- | --------------------------------------------------------- |
| 1 | 接上外网     | 宽带账号填什么？光猫哪个口？   | 账号 `051212345678`；标「**不是 Wi-Fi 密码，是宽带密码**」；接口选「光猫的 LAN 口」 |
| 2 | 给内网发地址   | 地址池写什么？会不会和自己冲突？ | 照着抄一段；起点建议 `本机前三段 + .100`（后端按真实 LAN IP 推，不写死）             |
| 3 | 能打开网址    | 用哪家 DNS？填几个？     | 六家一键选；不知道选哪个就 `223.5.5.5`；一个不通自动换另一个                      |
| 4 | 要不要 IPv6 | 开了能怎样？前缀填什么？     | `2408:8207:1234:5678::/64`；明确写「内网通告只能用 /64」               |

### 关键设计决策

1. **DNS 探测不说术语** —— `SERVFAIL` / `REFUSED` / 超时 / NXDOMAIN 全部翻译成  
   人话（「这个 DNS 服务器拒绝回答」/「超时没回应，可能是运营商屏蔽了它」）。
2. **IPv6 前缀强制 `/64`** —— RFC 4862 协议硬要求。填 `/80` 自动规范化**并说明  
   原因**；关闭 IPv6 时**保留已填前缀不删**。
3. **第 1 步顺带配好另外三样** —— 写 WAN 口的同一次操作里打开 IPv4 转发、  
   masquerade、MSS clamp。只拨号不打 NAT 是「拨上号但上不了网」，新手无法自诊断。
4. **地址池校验按数值比** —— `'192.168.1.9' > '192.168.1.100'` 字符串比是 True，  
   按字符串比会把合法地址池判成非法。
5. **报错能直接指导下一步** —— 「圈进本机自己」→ `会自己和自己抢 IP，请把起点往后挪`；  
   「跨网段」→ `前三段必须和本机一致`。
6. **拨号独立且必须二次确认** —— 保存 ≠ 拨号；要手打「拨号」两字；页面明示  
   「会短暂中断现有网络」。**半成功不回滚**（前面成功的步骤保持生效）。

### 架构约束

向导**不新增任何配置能力**，全部走 `act_apply({'live': True})` 这条唯一通道，  
没有第二套落盘逻辑。后端 `act_wizard`（`op` = `probe` / `apply_step` / `dial`），  
路由 `/api/wizard`（超时 dial 120s / apply_step 110s / probe 60s）。

## 三、全项目复查（任务 B）

### 发现并修复的 2 个真 bug

#### bug ①：`docker-compose-v2` 是 Ubuntu 包名

Debian 13 里叫 `docker-compose`（2.26.1）。**后果比"装不上"严重**：  
`apt-get install` 命令行里只要有一个包名查不到就**整条命令中止**，  
同命令里其它正常的包一个都不装。实测：

```
apt-get install --dry-run zip unzip 不存在的包名zzz
→ E: 无法定位软件包 不存在的包名zzz     （zip / unzip 也没装）
```

一个包名写错，整个「一键安装依赖」按钮全废。

**修复**：

- 新增 `_pkgs_available()` —— 用 `apt-cache show` 过滤出本机真有的包名
- `act_depcheck` 安装前过滤；过滤后为空时给明确原因（提示先 `apt-get update`）
- `DOCKER_PKGS` / `DEPS` 表保留双候选（跨发行版兼容）
- `control` / `app.js` / `build-deb.sh` 里用户可见的包名全部改对
- `_dev/t-deps.py` 新增 10 项断言钉死

#### bug ②：`_share_apply_file` 写 SMB / NFS 配置不是原子写

原实现 `with open(path, 'w')` 会**先把原文件截断成 0 字节**再逐块写入。  
两步之间如果 `smbd` / `nfs-server` 恰好 reload 或掉电，读到的是半截配置 ——  
轻则服务起不来，**重则按残缺的 share 定义把目录暴露出去**。

**修复**：改成与 `act_apply` 同一套原子写（同目录临时文件 → `os.replace`），  
并补上失败时清理残留临时文件。

**为什么之前没发现**：`act_apply` 走 `os.replace`，而 SMB/NFS 走 `act_share`  
自己的写盘逻辑 —— 两条路径只查了一条。这也是为什么"模块联动"必须按表比对  
而不是凭印象：`samba`/`nfs` 不在 `APPLY_SPEC` 里，很容易被当成"没问题"跳过。

`_dev/t-deps.py` 新增 5 项断言：`act_apply` 与 `_share_apply_file` 都必须  
"先写临时文件 + `os.replace`"，且不得再出现直接 `open(path,'w')` 覆写。
