## #69 磁盘与日志清理（菜单：系统 → 磁盘与日志清理）

**为什么需要它**：路由器是小硬盘设备，日志 / apt 缓存 / 临时文件是撑爆磁盘的
头号元凶，而磁盘满会导致 DHCP、日志、快照全部失效，且远在千里之外不好救。

**9 个清理项**（每项可单独开关、单独设保留天数）：

| 项 | 内容 | 默认阈值 |
|----|------|----------|
| ulog | 统一日志归档 | 3 天 |
| drouter_log | drouter 自身日志 | 7 天 |
| varlog | /var/log 下过期轮转件 | 14 天 |
| journal | systemd 日志 | `journalctl --vacuum-time` |
| apt | apt 缓存 | `apt-get clean` |
| snapdl | 快照下载临时文件 | 1 天 |
| tmp | /tmp 过期文件 | 3 天 |
| trash | 回收站 | 7 天 |
| core | 内核转储 | 7 天 |

**三条安全设计**：

1. **安全边界表** `CLEAN_FORBIDDEN`（14 个前缀）：`/etc`、`/boot`、`/usr`、`/var/lib/dpkg`、
   `/opt/drouter/backend` … 全部用 `realpath` 归一化后再比对前缀，
   任何软链接穿越都逃不掉。
2. **活跃文件只统计不清理**：正在写入的 `ulog.jsonl`、`drouter.log` 属于 `peek` 字段，
   页面如实显示「正在写入 1.4 MB（保留不删）」—— 否则用户会以为「占用 0」没风险。
3. **dry run 先行**：可以先试跑一次看「会释放多少」，确认无误再真删。

**真机实测**：磁盘 7.4%（6064/81442 MB），9 项合计可释放 **222.8 MB**；
试运行后磁盘占用 Δ=0 字节（确认一个文件都没删）；真实清理后核对文件确实消失。

**定时器**：`drouter-cleanup.timer` 默认开启，deploy.sh 会自动初始化策略。
触发方式可设「按磁盘水位」「按时间」「两者满足其一」。

## #70 内核转发与加速（菜单：系统 → 内核转发与加速）

五项内核级开关，每项都带**通俗说明**与**联动影响**（用户明确要求的）。

| 开关 | 我的默认 | 理由 |
|------|----------|------|
| IPv4 转发 | 开 | 路由器的本职工作 |
| IPv6 转发 | 开 | 同上 |
| BBR 拥塞控制 | 开 | 高延迟/丢包链路明显更好，副作用小 |
| SNMP 监控 | **关** | 多一个 UDP 161 监听就多一分风险 |
| （IPv4 masquerade） | 开 | 关了内网就上不了网 |
| （IPv4 MSS 钳制） | 开 | 专治「部分网站打不开、图片加载一半」 |
| （IPv6 NAT66） | **关** | IPv6 推荐端到端，开了 BT/P2P/远程桌面会失效 |
| （IPv6 MSS 钳制） | **关** | IPv6 靠 PMTUD 自己协商 |

### 本轮最重要的发现：IPv6 转发的致命联动

真机上 `ip -6 addr show ens18` 显示本机的 `2408:8340:.../64` 与 v6 默认路由
**都来自 `proto ra`（SLAAC）**，租期 86370 秒 ≈ 24 小时。

开启 `net.ipv6.conf.all.forwarding=1` 后，**内核会忽略 `accept_ra=1`**（默认值），
于是本机不再接受上游的路由通告 —— 租期一到，**整个 IPv6 就没了**。

修法：`_kern_sysctl_lines()` 在开启 v6 转发时自动追加
`net.ipv6.conf.all.accept_ra = 2`（「就算开了转发也照收 RA」），
并把这条写进页面的联动影响文案。这也是 OpenWrt / RouterOS 的标准做法。

**真机验收**：
```
生效前  ip_forward=0  ipv6_forwarding=0  拥塞=cubic  队列=fq_codel
保存后  ip_forward=1  ipv6_forwarding=1  拥塞=bbr    队列=fq   （accept_ra 一并写入）
关闭后  ip_forward=0  ipv6_forwarding=0  ← 关得掉
```
MSS / masquerade 的落点是 `nft_v4` / `nft_v6` 配置库（**不另存一份**，
避免两处打架），改完到「防火墙 IPv4 / IPv6」页点「保存并应用」生效。

## #71 Docker 引擎配置（菜单：工具 → Docker 引擎配置）

**先说一个前提**：这台机器上 **Docker 没装**（`docker` 命令不存在、
`/etc/docker/` 目录都不存在）。所以这一页做成了「**未安装也能预配置**」——
文件照常写到 `/etc/docker/daemon.json`，将来装好 Docker 一启动就生效。

### IPv6 一键开关

```json
{ "ipv6": true, "fixed-cidr-v6": "fdxx:xxxx:xxxx::/64", "ip6tables": true }
```

- 默认**关闭**：开了不等于能上 v6 外网，还得上游路由器配合
- 网段留空时，保存会**自动生成一个 ULA 私有 /48**（`fd` + 40 bit 随机数，RFC 4193）。
  用私有段而不是公网段，是因为公网段还需要上游做 NDP 代理 —— 家用环境多半没这条件
- `ip6tables: true` 会一起写：没有它 Docker 不会给容器生成 v6 规则，等于白开
- `experimental` **默认不写**，做成单独勾选项。只有 Docker 24/25 需要它来解锁
  ip6tables；26 起 ip6tables 已转正，多写这一项在个别版本上会让 dockerd 拒绝启动

### 国内镜像源切换 + 一键测速

7 个预设（腾讯云 / DaoCloud / 网易 / 中科大 / 南京大学 / 上海交大 / 阿里云占位），
可多选、可填自定义源。

**测速从这台路由器自己发起**（带 `--noproxy '*'`，不被环境代理掩盖），
打 Registry v2 的 `/v2/` 探针，**HTTP 200 或 401 都算可用**（探针本来就要求带凭证）。

真机实测结果（2026-09-29）：

| 源 | 结果 | 说明 |
|----|------|------|
| DaoCloud | ✅ 401 · 64 ms | 可用 |
| 南京大学 | ❌ 403 | 解析到 IPv6，返回的不是 Registry 应答 |
| 上海交大 | ❌ TLS 告警 | SSL routines::tlsv1 alert internal error |
| 腾讯云 / 网易 / 中科大 | ❌ 解析失败 | 上游 DNS（192.168.7.2）解析不了这三个域名 |
| 阿里云 | ⏭ 跳过 | 占位地址，需填自己的专属地址 |

> 这不是 bug —— 已用 `getent hosts` 逐个核对，确认上游 DNS 确实解析不了那三个域名。
> 这恰恰说明测速功能的价值：**镜像源的可用性会随运营商和时间变，只能以实测为准**。

### 顺带纳管的三项

- **日志滚动**（默认开，10m × 3 份）：容器日志是撑爆小硬盘的头号元凶
- **live-restore**（默认开）：重启 dockerd 时别把容器一起杀掉
- **默认网桥网段 bip**（默认不动）：专治 docker0 与局域网网段打架。
  填了会和本机现有网卡网段做重叠检测并告警

### 两条铁律

1. **用户自己写的键一律保留**：`data-root` / `insecure-registries` / `storage-driver`
   这类本页不管的键原样抄进结果，页面还会明确列出「有 N 个本页不管的键，会保留」。
   静默丢掉别人的配置是最糟的体验。
2. **保存只写盘，绝不自动重启**：重启会中断所有容器、重建 docker0、重插 iptables/nft 链。
   重启是独立按钮 + 二次确认弹窗；构建保护模式下直接拒绝。

每次保存自动备份（保留最近 5 份，`/var/lib/drouter/dcfg-backup/`），可一键还原。

### 「配置代码同时显示」

用户明确要求。做法是**预览一律调后端 `op=preview`**，前端不自己再拼一份 ——
否则两边逻辑迟早不一致，用户看到的代码和写进去的代码对不上。
页面上的 `<pre>` 随选项实时变化（250ms 防抖），保存后再用服务端返回的
真实落盘内容校准一次。单测里有「落盘内容与预览逐字节一致」的断言。

# #73 CUPS 打印服务 + USB RAW 直通（互斥二选一） ✅ 已完成并真机验收

## 需求理解

把这台路由器变成打印服务器：**CUPS 模式**（功能最全，手机/电脑免驱，有队列管理）
和 **USB RAW 直通模式**（最省资源、兼容性最好，客户端自己装驱动）**互斥二选一** ——
它们抢的是同一个 USB 打印机。

## 这台机器上的实测起点（决定了默认值怎么定）

| 项目 | 实测 | 含义 |
|------|------|------|
| CUPS | 2.4.10-3+deb13u2 已装且 active | 不用引导安装，直接可用 |
| 631 监听 | **只有 127.0.0.1:631** | 局域网里的电脑手机**全都连不上** —— 装了等于白装 |
| 队列 | `HP_OfficeJet_Pro_7740_series_44636D`，`Shared No` | 是靠 cups-browsed 自动发现的，但没共享出去 |
| USB 打印机 | **无**（PVE 虚拟机，lsusb 只有 QEMU Tablet） | RAW 模式下会如实提示「找不到 /dev/usb/lp0」 |
| socat | 1.8.0.3 已装 | RAW 直通不用再装 p910nd |
| avahi-daemon | active | 局域网发现（iPhone/Android 自动找到打印机）可用 |
| nftables | input 链 LAN 全放行 | 631 / 9100 不会被防火墙挡 |

## 我替用户做的判断（默认值）

| 项 | 默认 | 理由 |
|----|------|------|
| 工作模式 | CUPS | 功能最全、手机免驱；RAW 需要用户自己装驱动 |
| 允许局域网访问 | **开** | CUPS 出厂只听 127.0.0.1，不开这页就没意义 |
| 共享打印机 | 开 | 不共享的话局域网根本看不见它 |
| CUPS Web 界面 | 开 | 方便排障，关掉不影响打印 |
| **允许远程管理** | **关** | 安全红线：不该让同网段任何人都能增删队列 |
| cups-browsed | 开 | 你那台 HP 7740 就是靠它发现的 |
| RAW 端口 / 设备 | 9100 / `/dev/usb/lp0` | 行业标准端口 + usblp 默认节点 |

## 核心设计：为什么必须互斥

- CUPS 侧靠 **ipp-usb**（走 libusb）拿设备；
- RAW 侧靠内核 **usblp** 模块的 `/dev/usb/lp0`；
- 两边同时开的结局是**谁都打不出来**。

所以切模式时本页会把对面**停干净**：

| 切到 | 动作 |
|------|------|
| RAW | 停 + 禁用 `cups-browsed` / `cups.service` / `cups.socket` |
| CUPS | 停 + 禁用 `drouter-printer-raw.service` |
| 关闭 | 全部停 + 禁用，631 / 9100 都不再监听 |

## 关键安全边界：cupsctl 的 `Allow all`

`cupsctl --remote-any` 会把 `<Location />` 写成 **`Allow all`**（放行一切来源，
WAN 侧也能连上打印）。对一台路由器来说太宽了。本页在 cupsctl 之后**再收窄一层**
成 `Allow @LOCAL` —— 只有直连网段能访问，不会把打印机暴露到公网。
改完还会跑 `cupsd -t` 校验，校验不过就把改动前的备份自动还原。

## 本轮踩到并修掉的坑（都是真 bug，不是测试问题）

1. **从「关闭」切回 CUPS 时 cupsctl 必然失败** —— `cupsctl` 不是直接改配置文件，
   而是连到 cupsd 的本地 socket 下命令；cups 没在跑就报
   「无法连接服务器：错误的文件描述符」，而且失败后直接 return 会让 cups 一直停着，
   等于切了个寂寞。**修**：`_print_apply_cups` 先确认 cups 起来了再下命令。
2. **`printers.conf` 是 cupsd 延迟落盘的** —— 刚 `lpadmin` 加完的队列，
   `lpstat -p` 里已经有了、文件里还没有（实测要等 cupsd 重启才写进去）。
   只认文件的话用户会遇到「队列加了却看不见」。
   **修**：用 `LC_ALL=C lpstat -p` 补齐（这机器的 lpstat 默认是中文，
   必须强制 C locale 才可解析）；并且在增删队列后重启 cups 逼它落盘，
   否则删掉的队列还会继续显示在列表里。
3. **`(\S+?)` 配可选 `[.,]` 只吃到一个字母**（`idle` → `i`）——
   非贪婪量词遇到后续可选项就提前结束。改成 `([^\s.,]+)`。
4. **`int(port or 9100)` 又踩了 0 是 falsy 的老坑**（和 #71 同一个）。
5. **验收脚本自己的两个错**：`%s` 传了元组；以及把队列操作放在了 RAW 模式之后
   （那时 CUPS 已被停掉，`lpadmin` 必然失败）。已修，并把改动段包进 try、
   现场先落盘 JSON，保证崩溃也能还原。

# #74 AC/AP 管理中心（OpenSOHO） ✅ 已完成并真机验收

菜单：**服务 → AC/AP 管理中心**　接口：`/api/opensoho`　后端：`act_opensoho`

## 需求理解与边界

OpenSOHO 是一个单二进制（Go / PocketBase 内核）的 OpenWRT 集中控制器。AP 侧装
`openwisp-config` 后用共享密钥向它自注册，之后 Wi-Fi、VLAN、PoE 全在它自己的
控制台里配。

drouter 这里**只做托管，不重复实现**：

| 做 | 不做 |
|----|------|
| 装/升级/卸载二进制与 systemd 单元 | 重做一遍 Wi-Fi / SSID 配置界面 |
| 保管两把密钥与控制台管理员凭据 | 自己解析 AP 上报的数据 |
| 管启停、开机自启、监听地址与端口 | 替代 OpenSOHO 的控制台 |
| 调 REST API 把 AP / 客户端数量回显到本页 | —— |
| 给一个「打开控制台」的入口 | —— |

理由：重复实现一遍既做不好也维护不动，真正的配置界面就在它自己那儿。

## 探测阶段摸清的事实（决定了很多设计）

| 事实 | 影响 |
|------|------|
| **连 `--help` 都要 `OPENSOHO_SHARED_SECRET`** | 跑任何子命令（含 `-v`、`superuser`）都必须带上密钥环境 |
| `--dir` 默认值是 `/home/<用户>/pb_data` | 必须显式指定，否则 root 跑就落到 `/root` |
| **pb_migrations 解压到「工作目录」而不是 `--dir`** | 工作目录必须可写 → 后来踩了个大坑，见下 |
| `/api/health` **免鉴权**，返回 `{"code":200,...}` | 拿来做「到底起没起来」的判断最合适 |
| 集合共 29 个，真实名字是 `wifi_ssids` / `wifi_aps` | 文档里写的 `wifi` 其实不存在（404） |

## 本轮踩到并修掉的坑（4 个都是真 bug）

1. **服务起不来：`mkdir /opt/drouter/opensoho/pb_migrations: permission denied`**

3. **`systemctl restart` 返回 0 但服务秒退，页面显示「已安装并已启动」而端口没监听**

## 需求理解与边界

## 最关键的设计：部署是唯一能把用户关在门外的动作

换证书要**重启 drouter-web**，而一旦新证书有问题（私钥不配对、格式不对），
Web 就再也起不来 —— 你会被关在自己家的管理后台门外，只能跑机房接显示器。
所以部署前设了**四道闸**，部署后设了**一道验 + 一条退路**：

| 阶段 | 检查 | 不通过会怎样 |
|------|------|--------------|
| 闸 1 | 证书能被 openssl 解析 | 直接拒，不动磁盘 |
| 闸 2 | 有对应的私钥文件 | 直接拒 |
| 闸 3 | **证书与私钥的公钥配对** | 直接拒（这条最要命，配不上 Web 必起不来） |
| 闸 4 | 有效期覆盖当下 | 直接拒 |
| 动作 | 备份 → 临时文件 + `os.replace` 原子替换 → chown drouter | 中途断电也不会留下半个文件 |
| 验 | 重启后**真的握手一次**，比对指纹是不是新证书 | 指纹不对就认定失败 |
| 退路 | 自动从备份还原 + 再启一次 | 回到部署前的状态 |

还有一个必须处理的坑：重启 drouter-web 会把**这次 HTTP 响应一起带走**
（helper 与 web 在同一个 systemd cgroup 里）。这不是失败，结果已经写到
`/etc/drouter/ca/last-deploy.json` 了。所以前端要把「连接断了」和「真的失败了」
分开：`code` 是 `NET` / `PARSE` 就提示「正在重启，10 秒后自动刷新」，
否则才弹错误。

## 本轮踩到并修掉的坑（2 个都是真 bug，不是测试问题）

**1. 部署明明成功，却被判失败并回滚。**
`_ca_handshake` 取指纹时只算了前 16 字节，而 `_ca_x509_info`（走 openssl
`-fingerprint -sha256`）给的是完整 32 字节 —— 两个永远不相等，于是「指纹没变」
被当成失败，刚换好的证书又被还原回去。第一轮真机验收第一次跑就撞上了。
**修**：握手指纹改成完整 32 字节、冒号分隔大写，与 openssl 输出一字不差；
单测里补两条回归断言（格式一致 + 长度 95 字符）。

**2. openssl verify 的编号表填错了。**
我第一版凭印象填：`21` 写成「链里有证书不是 CA 证书」（其实那是 `24`），
`27` 写成「已吊销」（其实那是 `23`）。结果私有 CA 签发的证书 —— 这是本功能
最主要的用法 —— 被标成一条完全不相干的错误说明。
**修**：按 `x509_vfy.h` 重写整张 `SSL_VERIFY_CN`（`21`=找不到颁发者、
`23`=已吊销、`24`=链里有一张不是 CA 证书、`62`=主机名不匹配……）。
另外「信任链」这一项的说明也改了：自签 / 私有 CA 属于正常现象，点了会标红但
**加密本身是生效的**，把根证书装进设备就不再提示 —— 否则用户会以为是坏掉了。

# #84 新手向导（菜单：概览 → 新手向导，排在第一位） ✅ 已完成并真机验收

## 需求理解

中国大陆家庭宽带上网，新手卡住的就四件事：**从哪接宽带 / 内网怎么发地址 /
域名怎么解析 / 要不要 IPv6**。这四项在别处都有专业页面，但术语密集、字段多、
错了也没人告诉你错在哪。新手向导把这四步串成一条直线，每一步都给**可以照抄的
范例**，并且**边填边体检**（探测真实网卡 / 真实解析 / 真实连通性），而不是填完
保存了才发现不通。

## 为什么放在「概览」组第一位

新手打开 Web 后台的第一眼应该看见它。放系统组或工具组都要先知道去哪找，
那就失去意义了。`needSave: false` —— 向导每步自带「保存并生效」按钮，
不需要页面底部那条全局动作条（避免「我点了保存到底存没存」的困惑）。

## 四步各自解决什么

| 步 | 标题 | 解决的原始困惑 | 给的范例 |
|---|---|---|---|
| 1 | 接上外网 | 宽带账号填什么？光猫哪个口？ | 账号 `051212345678`；密码下面标「不是 Wi-Fi 密码，是宽带密码」；接口选「光猫的 LAN 口」 |
| 2 | 给内网发地址 | 地址池写什么？会不会和自己冲突？ | 照着抄一段；起点建议 `本机前三段 + .100`（由后端 lan_ip 推出来，不写死） |
| 3 | 能打开网址 | 用哪家 DNS？填几个？ | 六个常用服务商一键选；不知道选哪个就 223.5.5.5；一个不通自动换另一个 |
| 4 | 要不要 IPv6 | 开了能怎样？前缀填什么？ | `2408:8207:1234:5678::/64`；明确写「内网通告只能用 /64」 |

## 关键设计决策

**1. 第 3 步的 DNS 探测不说术语。**
`dig` 返回 SERVFAIL / REFUSED / 超时 / NXDOMAIN 全部翻译成人话
（"这个 DNS 服务器拒绝回答"/"超时没回应，可能是运营商屏蔽了它"），
新手看不懂 `SERVFAIL`。

**2. 第 4 步前缀强制 /64 —— 这是协议硬要求，不是我们挑剔。**
RFC 4862 规定 RA 通告的前缀长度必须是 64。用户填 `/80` 时自动规范化成 `/64`
**并说明原因**；关闭 IPv6 时**保留已填的前缀不删**（下次想开不用重填）。

**3. 第 1 步顺带把「能上网」的另外三样一起配好。**
写 WAN 口的同时打开 IPv4 转发、masquerade、MSS clamp。只配拨号不打 NAT 是
「拨上号但访客上不了网」，新手无法自诊断。

**4. 地址池校验必须按数值比，不能按字符串比。**
`'192.168.1.9' > '192.168.1.100'` 字符串比是 True（`'9' > '1'`），
按数值比才是 False。按字符串比会把合法地址池判成非法。

**5. 校验分两类，报错口径不同。**
「圈进了本机自己」→ `会自己和自己抢 IP，请把起点往后挪`；
「跨网段」→ `前三段必须和本机一致`。都是能直接指导下一步动作的话。

**6. 拨号是独立动作，且必须二次确认。**
保存配置 ≠ 拨号。点拨号要手打「拨号」两个字确认，页面写明
「会短暂中断现有网络」。**半成功不回滚**：四步里某步失败，前面已成功的步骤
保持生效（新手最怕的是"点了个按钮，全没了"）。

## 真 bug ①：`docker-compose-v2` 是 Ubuntu 包名，Debian 13 叫 `docker-compose`

**后果比"装不上"严重**：`apt-get install` 命令行里只要有**一个**查不到的包名，
就**整条命令中止**（`E: 无法定位软件包`），同命令里其它正常包**一个都不装**。
实测：
```
apt-get install --dry-run zip unzip 不存在包名zzz
→ E: 无法定位软件包 不存在包名zzz   （zip / unzip 也没装）
```
所以一个包名写错，整个依赖安装按钮全废。

**修**：
- `DOCKER_PKGS` 保留双候选（`docker.io` / `docker-compose` / `docker-compose-v2`）
- 新增 `_pkgs_available()`：用 `apt-cache show` 过滤出本机真有的包名
- `act_depcheck` 安装前过滤；过滤后为空时给出明确原因（提示先 `apt-get update`）
- `_docker_pkg_state` 用过滤后的列表拼安装命令
- `DEPS` 表里 compose 项写双候选 `docker-compose|docker-compose-v2`
- `control` / `app.js` / `build-deb.sh` 里的用户可见包名全部改对
- 单测 `t-deps.py` 新增 10 项断言钉死

## 真 bug ②：`_share_apply_file` 写 SMB / NFS 配置不是原子写

**问题**：原实现 `with open(path, 'w')` 会**先把原文件截断成 0 字节**，
再逐块写新内容。两步之间如果 `smbd` / `nfs-server` 恰好 reload 或掉电，
它读到的是半截配置 —— 轻则服务起不来，**重则按残缺的 share 定义把目录暴露出去**。

**修**：改成与 `act_apply` 同一套原子写（同目录临时文件 → `os.replace`），
并补上失败时清理残留临时文件。

**为什么之前没发现**：`act_apply` 走的是 `os.replace`，而 SMB/NFS 走 `act_share`
自己的写盘逻辑 —— 两条路径，只查了一条。这也是为什么"模块联动"要按表比对而不是
凭印象：`samba`/`nfs` 不在 `APPLY_SPEC` 里，容易被当成"没问题"跳过。

单测 `t-deps.py` 新增 5 项断言：`act_apply` 与 `_share_apply_file` 都必须
"先写临时文件 + `os.replace`"，且不得再出现直接 `open(path,'w')` 覆写。

## 不是 bug 的两处（记下来免得下次重查）

- **`samba` / `nfs` 不在 `APPLY_SPEC`**：它们走 `act_share` 自己的 plan /
  写盘 / 重启逻辑，不经 `act_apply`，这是刻意的设计而非遗漏。
- **`nfs` / `samba` 的写盘不拍快照**：与 `act_apply` 的"应用前自动快照"不同，
  共享配置改动量小且可人工回滚，未纳入快照策略。
