## 一、30 秒上手

### 完全没配过路由器？先走「新手向导」

菜单 **概览 → 新手向导**（第一位）。四步走完就能上网，每步都给可以照抄的范例，
并有实时体检：

| 步 | 标题 | 它会问你 | 范例 |
| -- | -- | -- | -- |
| 1 | 接上外网 | 宽带从哪进来（PPPoE / 自动 / 静态） | 账号 `051212345678`；**不是 Wi-Fi 密码，是宽带密码**；接口选「光猫的 LAN 口」 |
| 2 | 给内网发地址 | 地址池从哪到哪 | 照着抄一段；起点建议 `本机前三段 + .100`（后端按真实 LAN IP 推出来） |
| 3 | 能打开网址 | 用哪家 DNS | 六个常用服务商一键选；不知道选哪个就 `223.5.5.5`；一个不通自动换另一个 |
| 4 | 要不要 IPv6 | 要不要开、前缀是什么 | `2408:8207:1234:5678::/64`；**内网通告只能用 /64** |

三条要记住的：

- **保存 ≠ 拨号**。第 1 步填完先保存，再单独点「开始拨号」（要手打「拨号」两个字
  确认，会短暂中断现有网络）。
- **某一步失败不影响前面已成功的步骤**（半成功不回滚）。新手最怕"点了个按钮全没了"。
- **向导只做最基础的四件事**：更多功能（多拨、QoS、DPI、端口转发、共享…）
  配完之后回各自页面调。

### 已经会用路由器？直接走标准流程

| 步骤 | 操作                                        | 说明                   |
| -- | ----------------------------------------- | -------------------- |
| 1  | 打开 `https://192.168.7.3:8443`             | 自签证书，浏览器需点"继续访问"     |
| 2  | 用 `admin` / `admin123` 登录                 | **登录后请立刻改密码**（系统设置页） |
| 3  | 在「网卡与桥接」页确认 `ens18`=LAN、`ens19`=WAN       | 依据 MAC 识别，换硬件也不会错乱   |
| 4  | 在「WAN 口」页填写 **宽带账号 / 密码**，点右下角「仅保存」       | 只写盘，不拨号              |
| 5  | 点「保存并应用」→「开始拨号」                           | 正式切换，此时会断网重连         |
| 6  | 拨号成功后，逐项启用 DHCP / IPv6 / UPnP / NTP       | 每项都有二次确认与失败自动回滚      |
| 7  | （可选）接口 → PPPoE 多拨，多条会话聚合带宽                | 需运营商允许并发拨号           |
| 8  | （可选）服务 → QoS 智能限速，抗 bufferbloat / 按 IP 限速 | CAKE 或 HTB，二者互斥      |
| 9  | （可选）服务 → DPI 识别库，装 nDPI 特征库               | 国内网络请先「测速」挑加速前缀      |

> 当前两张网卡：`ens18`（LAN，192.168.7.3）+ `ens19`（WAN，待 PPPoE 拨号）。
>   
> `ens19` 已认领为 WAN 且处于安全状态（无 IP、NetworkManager 未托管、默认路由仍走 ens18）。

### 关键模块速查

| 模块       | 菜单位置          | 一句话用途                           | 关键前提                                        |
| -------- | ------------- | ------------------------------- | ------------------------------------------- |
| **新手向导** | **概览 → 新手向导（首位）** | 四步解决最基础的上网：外网 / 内网地址 / DNS / IPv6 | 每步都有范例与体检；**保存 ≠ 拨号**，拨号要单独确认 |
| PPPoE 多拨 | 接口 → PPPoE 多拨 | 同一账号/多账号并发拨号，叠加带宽               | **运营商必须允许并发**；部分省份限制 1 条                    |
| QoS 智能限速 | 服务 → QoS 智能限速 | 抗 bufferbloat、游戏/DNS 插队、按 IP 限速 | 需关闭 **flowtable 软加速**（会绕过 netfilter 导致打标失效） |
| DPI 识别库  | 服务 → DPI 识别库  | 按应用识别流量（nDPI/Suricata）          | 4GB 内存建议只装 nDPI；需选可用加速前缀                    |

## 二、目录与文件

```
/opt/drouter/
├── backend/
│   ├── drouter-web.py      # Web 后端（低权用户 drouter 运行，~21MB）
│   ├── drouter-helper.py   # root 特权白名单执行器（唯一提权入口）

├── web/                    # 前端（index.html + app.css + app.js，纯静态）
├── data/drouter.db         # SQLite：配置、管理员、审计、快照索引
├── snapshots/              # 应用前自动快照（可一键回滚）
├── certs/                  # 自签 TLS 证书（含 SAN）
└── bin/sync-isp-dns.sh     # 把 pppd 拿到的运营商 DNS 同步给 dnsmasq

/etc/drouter/
├── BUILD_MODE              # ★ 存在 = 构建保护模式开启
└── generated/isp-dns.conf  # 运营商 DNS 注入点

/var/log/drouter/           # 结构化 JSONL 日志（任何 AI 都能读）
```

## 三、构建保护模式（核心安全机制）

`/etc/drouter/BUILD_MODE` 是一个全局熔断开关。存在时：

| 被拦截的行为                                           | 原因                   |
| ------------------------------------------------ | -------------------- |
| 启动 dnsmasq / radvd / dhcpcd / miniupnpd / chrony | 会抢 53/67 端口，可能引发广播风暴 |
| 任何 `live=true` 的应用                               | 会真正改变网络状态            |
| 网卡迁移、PPPoE 拨号控制                                  | 会断开现有链路              |
| 关机 / 重启 / 软件升级                                   | 会中断你的局域网             |

**不会被拦截**：写配置文件、语法预检、生成快照、回滚、查看状态、编辑用户。

解除保护（由我或你在系统设置页操作）：

```bash
# 开启保护
sudo touch /etc/drouter/BUILD_MODE
# 解除保护
sudo rm -f /etc/drouter/BUILD_MODE
```

## 四、安全模型

```
浏览器 ──HTTPS 8443──▶ drouter-web.py（用户 drouter，非特权）
                              │  sudo -n（NOPASSWD 仅限 helper）
                              ▼
                    drouter-helper.py（root，动作白名单）
                              │  subprocess 列表形式，绝不做 shell 拼接
                              ▼
                     实际系统操作
```

- **白名单动作**：只识别固定动作名，参数逐个校验（IP / CIDR / 网卡名 / MAC / 整数范围）。
- **无 shell 拼接**：所有外部命令使用 `subprocess` 列表形式，杜绝注入。
- **会话**：60 分钟过期，登录失败 5 次锁定 10 分钟，PBKDF2-SHA256(180k) 存密码。
- **审计**：所有提权动作写入 `/var/log/drouter/audit.jsonl`。
- **系统加固**：`ProtectSystem=true`、`ProtectHome=read-only`、`NoNewPrivileges` 保持可用、内存上限 160M、CPU 40%。

## 五、单管理器原则

每个网络功能只有一个组件负责，避免互相打架：

| 功能              | 唯一管理器            |
| --------------- | ---------------- |
| 网卡 / 桥接 / 地址    | NetworkManager   |
| 防火墙（v4/v6）      | nftables         |
| DHCPv4 + DNS 转发 | dnsmasq          |
| IPv6 RA         | radvd            |
| DHCPv6-PD 客户端   | dhcpcd           |
| IPv6 地址池        | 内核 + radvd（自动生成） |
| UPnP            | miniupnpd        |
| PPPoE           | pppd             |
| NTP             | chrony           |

## 六之二、一键运维脚本 drouter-ctl

随包安装后会提供 `drouter-ctl` 命令（也在 `/opt/drouter/scripts/drouter-ctl.sh`），
  
把安装、卸载、修复、更新、状态五件事收成一个入口。

```bash
drouter-ctl install      # 交互式安装
drouter-ctl uninstall    # 卸载（保留配置与日志）
drouter-ctl uninstall --purge   # 连配置、快照、日志一起清掉
drouter-ctl repair       # 修复：重部署 + 修权限 + 重建单元 + 校验
drouter-ctl update       # 更新：先自动快照，再部署新版本
drouter-ctl status       # 查看服务 / 端口 / 主题 / 安全红线
```

### install 会问什么

| 提问          | 默认值                      | 说明                         |
| ----------- | ------------------------ | -------------------------- |
| LAN 网卡      | 探测到的第一块                  | 内网接口，如 `ens18`             |
| WAN 网卡      | 空                        | 外网接口，可留空后在界面里选             |
| LAN 地址      | `192.168.7.3/24`         | 本机在内网的地址（IP/掩码位数）          |
| LAN 网关      | LAN 地址本身                 | 路由器对内网而言就是网关               |
| DNS         | `223.5.5.5,119.29.29.29` | 逗号分隔                       |
| 是否开 DHCP 池  | `N`                      | 默认不开，避免与现有 DHCP 冲突         |
| 地址池起止       | 网段推导                     | 仅在开启 DHCP 时询问              |
| Web 端口      | `8443`                   | 写入 `/etc/drouter/web-port` |
| 管理员账号       | `admin`                  |                            |
| 管理员密码       | 空（沿用 admin123）           | 至少 6 位                     |
| PPPoE 账号/密码 | 空                        | 只保存不拨号                     |

> 脚本**只写入配置，不会应用到系统**。装完请到界面的「应用配置」里确认后再下发，
>   
> 以免直接改动正在运行的网络。整个安装过程不会启用 dnsmasq / radvd / miniupnpd，
>   
> 也不会触碰 RealVNC 的 5900 端口。

## 六之三、打包成 .deb 与 Docker 镜像

```bash
# 1) .deb 安装包（在 Debian/Ubuntu 上执行）
bash packaging/build-deb.sh 1.0.5      # 产出 dist/drouter_1.0.5_all.deb
sudo apt install ./dist/drouter_1.0.5_all.deb
sudo apt purge drouter                 # 彻底卸载

# 2) 离线依赖包（目标机无外网时）
bash scripts/make-offline-deps.sh      # 产出 dist/offline-deps/
# 把整个目录拷到目标机后：
bash install.sh drouter_1.0.5_all.deb

# 3) Docker 镜像
bash packaging/build-docker.sh 1.0.5
docker run -d --name drouter --restart unless-stopped \
  --network host --cap-add NET_ADMIN --cap-add NET_RAW \
  -v drouter-data:/opt/drouter/data -v drouter-etc:/etc/drouter \
  drouter:1.0.5
```

`.deb` 的 `control` 里已声明完整 `Depends`（nftables、dnsmasq、ppp、pppoe、
  
radvd、miniupnpd、conntrack、ipset、sqlite3 等），`apt install` 时自动补齐；
  
`postinst` 会自动完成部署并启动管理后台，同样遵守「不启动 DHCP/DNS」的红线。

**依赖分级的取舍**：`apt` 默认会连 `Recommends` 一起装，所以 `Recommends` 里只放
不带守护进程的工具（tcpdump、jq、htop、iotop、nvme-cli、lm-sensors）。
`smartmontools` 装完会**自动拉起 `smartd` 常驻服务**，对一台路由器是意料之外的
负担，因此降级到 `Suggests`，需要时手动 `apt install smartmontools`。

**容器端口**：`DROUTER_WEB_PORT` 只在**首次启动**时播种进 `/etc/drouter/web-port`，
随后容器入口会把它 `unset` 掉。原因是后端 `load_web_port()` 里环境变量优先级高于
配置文件，留着它会让「在界面里改端口」看起来改了没生效。
对应的 `HEALTHCHECK` 也读实际端口，不会因改端口而永远报 unhealthy。

## 六之四、手机访问与适配

手机浏览器直接访问 `https://<路由器 IP>:8443/` 即可，界面会自动适配窄屏：

| 元素 | 宽屏（>760px） | 窄屏（≤760px） |
|------|----------------|----------------|
| 侧边栏 | 固定 236px，可折叠成图标栏 | 变抽屉，点左上 ☰ 滑出，点遮罩 / Esc / 选菜单自动收起 |
| 内容区 | 多列栅格 | 单列堆叠 |
| 表格 | 直接铺满 | 自动套一层横向滚动容器，左右滑动查看 |
| 表单 | 一行多项 | 单列，输入框放大到 16px（避免 iOS 自动缩放） |
| 底部操作条 | 单行 | 换行铺满，按钮放大到 42px 便于点按 |
| 弹窗 / 提示 | 居中定宽 | 近满屏、可滚动，避开刘海与底部安全区 |

几个实现上的取舍：

- **抽屉不复用「折叠」状态**：窄屏点 ☰ 只切抽屉，不写 `localStorage`，
  否则把窗口拉回宽屏时会莫名变成折叠态。
- **表格滚动用统一包裹**：全站 20 多处表格（含 ajax 异步刷新的租约表、容器表），
  逐个改渲染代码不现实，改为渲染后由 `MutationObserver` 统一套 `.tw` 容器，
  异步回填的表格也能覆盖到，且重复执行是幂等的。
- **底部留白**：内容区底部预留了操作条高度 + `env(safe-area-inset-bottom)`，
  避免 iPhone 上最后一行被操作条或小黑条挡住。

> 管理后台是响应式布局，不是独立手机版：所有功能在手机上都能用，
> 只是复杂表格需要横向滑动。改配置这种精细操作仍建议在电脑上做。

## 七、快照与回滚

快照采用**三层全覆盖**设计，确保「快照能完整代表当时的全部用户设置」：

| 层      | 内容                                                                                                              | 说明                                                                                                            |
| ------ | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 配置库层   | `/opt/drouter/data/drouter.db`                                                                                  | 界面里所有模块配置：DHCP/DNS、防火墙 v4/v6、WAN/LAN、IPv6 与 RA、UPnP、NTP、网卡角色、访问范围、Web 端口等。用 `sqlite3.backup()` 做一致性备份，回滚时整体还原 |
| 系统文件层  | `/etc/dnsmasq.d/`、`/etc/nftables.d/`、`/etc/ppp/`、`/etc/radvd.conf`、`/etc/dhcpcd.conf`、`/etc/systemd/network/` 等 | 由配置库渲染出的原生配置文件                                                                                                |
| 账号与审计层 | `chap-secrets` / `pap-secrets` / `hostname` / `timezone` / `rescue.conf`                                        | 宽带凭据、主机名、时区、救援配置                                                                                              |

### 手动回滚

1. Web 界面「系统设置 → 配置快照与回滚」选择快照 → 一键回滚；
2. 或 SSH 执行：

```bash
sudo python3 /opt/drouter/backend/drouter-helper.py snapshot_list '{}'
sudo python3 /opt/drouter/backend/drouter-helper.py rollback '{"ts":"20260928-154621"}'
```

回滚前系统会自动再拍一张 `before-rollback` 快照，不满意还能退回来。

### 自动快照（默认开启）

| 项目    | 默认值                      | 说明                                                    |
| ----- | ------------------------ | ----------------------------------------------------- |
| 开关    | **开启**                   | 界面可随时关闭                                               |
| 快照时间  | 每 6 小时                   | 定时器 `drouter-snapshot.timer`，1–168 小时可调               |
| 过期时间  | 7 天后自动删除                 | `keep_days`，0 = 不按时间清理                                |
| 最多保留  | 30 份                     | 仅对自动快照计数，手动快照不占配额                                     |
| 存放路径  | `/opt/drouter/snapshots` | 可自定义，仅限 `/opt /srv /var/backups /mnt /media /home` 之下 |
| 应用前快照 | 开启                       | 每次「保存并应用」前先拍一张                                        |

还可**下载到本地电脑**：快照列表中每份都有「下载」按钮，导出为 `drouter-snapshot-<时间>.tar.gz`。

## 七之二、紧急救援通道

当配置失误把网络"打崩"（网络风暴、IP 冲突、路由环路、防火墙锁死、Web 打不开）时，常规手段已经进不去路由器。**紧急救援通道**是一条独立于 WAN/LAN 的应急入口。

**默认关闭**，需在「系统设置 → 紧急救援通道」勾选开启。

| 项目   | 默认值              | 说明                                   |
| ---- | ---------------- | ------------------------------------ |
| 虚拟地址 | `169.254.0.1/16` | 链路本地地址，不参与默认路由、不受 nftables 正常链路规则影响  |
| 备用地址 | `10.99.99.1/24`  | 需要在 PVE / 物理网络内直连时使用                 |
| 端口   | 8888             | 避开 22/53/67/68/80/443/5900/8080/8443 |
| 生效网卡 | 全部物理网卡（自动）       | 在每张网卡上加别名地址 → **插任一口皆可访问**           |

**使用方式**（插任意网口）：

```
http://169.254.0.1:8888/
http://169.254.0.1:8888/?restore=1      # 直达一键还原页
```

进入后可读取**全部快照**列表，一键还原任意一份并自动重启（`auto_reboot` 可关）。

**安全约束**：仅允许救援网段来源访问（127./169.254./救援网段），还原需填写确认短语「确认还原」，快照编号严格校验。还原后会自动重启，让设备恢复到可用状态。

## 八、RealVNC 保护策略

`RealVNC Server 6.11.0.47988` 已安装并运行于 5900，**本项目不触碰它**：

- 不 `apt-mark hold` 任何包（参考方案里的做法会导致后续升级全面失败）；
- 不在安装脚本里 stop/disable VNC；
- 系统更新页只做**只读风险提示**，提示升级 desktop 依赖时可能影响 VNC，由你决定是否更新。

## 九、故障排查速查

| 现象                    | 原因                               | 处理                                                                                     |
| --------------------- | -------------------------------- | -------------------------------------------------------------------------------------- |
| 打不开 8443              | 服务未起 / 防火墙                       | `systemctl status drouter-web`；本机是 LAN 口，防火墙未启用，多半是服务问题                                |

### UPnP 配置项（miniupnpd 2.3.x，Debian 13 nftables 后端）

render.py 生成的 `/etc/miniupnpd/miniupnpd.conf` 只允许出现下列项，写错任何一项都会导致服务启动 **failed**：


| 正确选项                                    | 说明                                                 |
| --------------------------------------- | -------------------------------------------------- |
| `ext_ifname`                            | WAN 口（如 `ppp0`）                                    |
| `listening_ip`                          | **必须是网卡名**（如 `ens18`）；写 IP 会告警且禁用 SSDPv6           |
| `http_port`                             | UPnP HTTP 端口。**不是 `port=`** —— 旧名会被静默忽略            |
| `enable_upnp` / `enable_natpmp`         | 两项都 `no` 时进程会打印 `Why did you run me anyway?` 后正常退出 |
| `secure_mode`                           | 客户端只能映射自己的 IP                                      |
| `upnp_forward_chain`                    | nftables forward 链名                                |
| `upnp_nat_chain`                        | nftables NAT 链名                                    |
| `upnp_nat_postrouting_chain`            | nftables postrouting 链名                            |
| `system_uptime` / `lease_file` / `uuid` | 常规项                                                |
| `allow` / `deny`                        | 权限规则，**必须写**，否则等于对全网开放                             |

> ⚠️ `upnp_nat_prerouting_chain` **不存在于 2.3.x**（曾误写入，导致服务 `failed`）。nftables 后端无需单独指定 prerouting 链。

### QoS / PPPoE 多拨 / DPI 常见问题（第五轮新增）

| 现象                                                             | 原因                                                               | 处置                                                                            |
| -------------------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| QoS 保存报 `Permission denied: /var/tmp/...`                      | `/var/tmp` sticky 位 + `fs.protected_regular=2`，root 无法覆写低权用户遗留文件 | **已修复**：改用 `/run/drouter-helper/`。若升级前遗留脏文件，`rm -f /var/tmp/drouter-*.nft` 即可 |
| QoS 保存报 `cache initialization failed: Operation not permitted` | `nft -c` 需要 netlink 缓存权限（受限环境）                                   | **已修复**：自动降级为影子表真实加载校验，不影响正常环境                                                |
| QoS 启用了但 DSCP / IP 限速不生效                                       | **flowtable 软加速正在运行**，已建立连接绕过 netfilter 钩子                       | 到「概述 → 网络状态」关闭软加速；或在 QoS 页勾选"我了解冲突，仍然继续"                                      |
| QoS 规则出现重复条目                                                   | `nft -f` 是追加语义                                                   | **已修复**：加载前先 `nft delete table inet drouter_qos`                              |
| QoS 启用后网页/游戏变慢                                                 | 上行带宽填得比实际大（运营商实测）                                                | 把上行填成实测值的 **85%~90%**，CAKE 靠这个算排队延迟                                           |
| PPPoE 多拨显示「未连接」并反复重拨                                           | 运营商拒绝同账号并发                                                       | 减少会话数；先确认 1 条能拨通；部分省份限制为 1                                                    |
| PPPoE 多拨生效后部分站点打不开                                             | 策略路由未正确挂接（回包走错会话）                                                | 检查 `ip rule show` 是否有 `from <本端IP> lookup 10x`；重拨一次触发 ip-up 钩子                |
| DPI 更新全部超时                                                     | 国内直连 GitHub 不通 / 所选前缀失效                                          | 点「测速」挑最快的；或选自定义前缀填自建代理                                                        |
| DPI 测速显示可用但真下载失败                                               | 部分加速**不代理 `codeload.github.com`**                                | **已修复**：测速 URL 已改用与真实下载同形的 `github.com/.../archive`                           |

### PPPoE 多拨原理速览（排错必备）

```
pppd（每条会话一个 systemd 单元）
  └─ drouter-wan1..N        独立 ppp 接口
       ├─ 路由表 101..10N     ip route add default via <peer> dev <iface> table 10x
       └─ ip rule from <本端IP> lookup 10x     ← 关键！保证回包原路返回
                                                        ↑
                                    没有它 = A 会话出的包从 B 会话回 → 连接重置
```

- 钩子脚本：`/etc/ppp/ip-up.d/drouter-pppm-route`（拨通时挂接）、`ip-down.d/`（断开时清理）
- 查看某会话日志：界面「日志」按钮，或 `journalctl -u drouter-pppoe@1.service -n 60`

### 第五轮专用验证脚本（`_dev/`，需 root）

```bash
bash _dev/rsudo.sh "bash /tmp/t-qos.sh"         # QoS CAKE：保存→启用→幂等→停用
bash _dev/rsudo.sh "bash /tmp/t-qos-htb.sh"     # QoS HTB：按 IP 限速全链路
bash _dev/rsudo.sh "bash /tmp/t-qos-switch.sh"  # QoS 模式双向切换

bash _dev/rsudo.sh "bash /tmp/t-dpi.sh"         # DPI get/plan/test/log
```

> 提示：`sim-ui.js` 使用 Node 内置 `http` 模块，需指向**明文 HTTP 8080**（HTTPS 8443 会 ECONNRESET）。
>
> 排查经验 1：修改配置渲染器后务必做一次**语法级试跑**（如 `miniupnpd -f /etc/miniupnpd/miniupnpd.conf -d`）。配置项名写错时服务只会 `failed`，日志埋在 journal 里，很容易被误判为"无关紧要的 inactive"。
>
> 排查经验 2：**不要用 `/tmp` 或 `/var/tmp` 存放 helper 的中间文件**。这两个目录带 sticky 位，配合 `fs.protected_regular=2`，root 无法覆写低权用户留下的同名文件，会报看起来莫名其妙的 `Permission denied`。统一用 `/run/drouter-helper/`。
>
> 排查经验 3：`X-Token`（不是 `Authorization: Bearer`）是 Web API 的鉴权头。用 curl 自测时写错会得到「登录已过期」，容易误判为会话问题。
